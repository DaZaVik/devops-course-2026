# Сравнение Git и SVN

## 1. Почему ветвление в Git считают дешёвым
В Git ветка — лёгкий указатель на коммит. Она создаётся локально, без копирования всех файлов и без обращения к серверу.

Утверждение, что SVN обязательно копирует все файлы и поэтому ветки всегда «дорогие», неточно. Серверный `svn copy` использует cheap copies: новую ссылку на существующее дерево. Он тоже экономен по времени и месту. Отличие — централизованный процесс: создание ветки на сервере требует доступа к репозиторию, а локальная рабочая копия обычно не содержит всей истории. Копирование каталога на клиенте действительно может занимать время.

## 2. Можно ли сделать коммит SVN без интернета
Коммит SVN требует доступа к центральному репозиторию. Если сервер доступен только через интернет, без интернета коммит невозможен. Если он находится в локальной сети или доступен по file:// на том же компьютере, интернет не нужен. Без доступа к репозиторию можно редактировать файлы, но нельзя сохранить новую серверную ревизию.

## 3. Когда SVN может быть предпочтительнее
SVN может подходить для действующей централизованной инфраструктуры, где миграция не окупается, нужны права доступа к отдельным каталогам, частичные рабочие копии или блокировка плохо сливаемых бинарных файлов. Выбор зависит от рабочего процесса, а не только от возраста системы.
